# External models catalog (Anthropic / Google / Yandex) — design

Дата: 2026-05-27
Ветка: polymind

## Цель

Добавить в список моделей плагина PolyMind топовые модели трёх внешних провайдеров —
Anthropic, Google, Yandex — как **каталог-тизер** в настройках. Реальной интеграции их
API в этой задаче нет: модели показываются как «coming soon», их нельзя выбрать и
отправить запрос.

## Контекст и находки

- `models.json` в корне репозитория **не используется** нигде в коде и к тому же
  содержит невалидный JSON (падает `JSON.parse`). Он не является источником списка
  моделей. (Чистка/исправление — вне scope этой задачи, отмечено ниже.)
- Список моделей формируется динамически из Groq API и хранится в
  `settings.groqAvailableModels` (`data.json`).
- Кнопка refresh (`GroqChatSettingsTab.ts:~381`) **полностью перезаписывает**
  `settings.groqAvailableModels` ответом API — любые «дописанные» модели исчезнут при
  обновлении. Поэтому каталог нужно домерживать при каждом построении списка.
- Отправка сообщений идёт только в Groq (`groqService.ts:~110`). Активная внешняя модель
  привела бы к ошибке Groq. Поэтому внешние модели — **неактивные**.

## Дизайн

### 1. Статический каталог — `src/data/externalModels.ts`

Экспортирует массив `GroqModelInfo[]` с топовыми моделями провайдеров. Поля:

- `isExternal: true` — новый флаг (добавляется в интерфейс `GroqModelInfo`).
- `isActive: false` — не попадает в селектор чата (он фильтрует по `isActive`).
- `isPreview`/метка — отображается как «(coming soon)».
- `owned_by` / `developer.name` — для группировки по провайдеру в таблице настроек.

### 2. Мерж без затирания — хелпер `mergeExternalModels(apiModels)`

Чистая функция (`src/utils/modelUtils.ts` или рядом с каталогом): принимает список
моделей из API, возвращает `[...apiModels, ...externalModels]` без дублей по `id`.
Вызывается в двух местах:

- при начальном построении списка моделей в настройках;
- в обработчике refresh, после маппинга API-моделей, перед `saveSettings()`.

Так каталог переживает refresh, но не сохраняется как «настоящие» Groq-модели в смысле
возможности отправки (они неактивны).

### 3. Безопасность отправки

Внешние модели неактивны → не попадают в дропдаун чата → отправить нельзя. В таблице
каталога настроек (`addModelListBlock`) они отображаются с меткой «coming soon» и, по
возможности, без чекбокса активации (или с заблокированным чекбоксом). Локализация
метки — для `ru` и `en`.

## Состав каталога (только топовые/актуальные)

| Провайдер | Модели                                               |
| --------- | ---------------------------------------------------- |
| Anthropic | Claude Opus 4.7, Claude Sonnet 4.6, Claude Haiku 4.5 |
| Google    | Gemini 2.5 Pro, Gemini 2.5 Flash, Gemini 2.0 Flash   |
| Yandex    | YandexGPT 5 Pro, YandexGPT 5 Lite                    |

Без legacy-версий (Claude 3.x, Gemini 1.5, YandexGPT 4 и т.п.).

## Тестирование (пункт 3 задачи)

Сейчас в проекте нет ни тест-раннера, ни тестов. В рамках этой задачи:

- Настроить раннер (Vitest — лёгкий, ESM-friendly, ставится как minor dev-зависимость;
  мажорные обновления существующих пакетов не трогаем).
- Добавить npm-скрипт `test`.
- Покрыть тестами **новый код**:
  - `externalModels` — каталог валиден (все записи `isExternal`, `isActive:false`,
    непустые `id`/`name`, уникальные `id`).
  - `mergeExternalModels` — домерживает каталог, не плодит дубли по `id`, сохраняет
    порядок API-моделей.

## Вне scope (зафиксировано, не делаем сейчас)

- Реальная интеграция API Anthropic/Google/Yandex.
- Мажорные обновления зависимостей (`groq-sdk`, `typescript`, `eslint`).
- Чистка/исправление мёртвого `models.json`.
- Прочие пункты аудита (контекст диалога, валидаторы ключа и т.д.).
